# MiniMax AI 动作表情开发版

## 接入范围

独立分支 `codex/minimax-ai-creation` 中增加真实产品页面 `ai.html`、Node 服务端和现有视频工作台的直接导入。当前线上版本尚未包含 AI 页面。

- 文生：MiniMax-Hailuo-2.3，6 秒、768P；图生：MiniMax-Hailuo-2.3-Fast，6 秒、768P。
- 三条可修改玩法：我只是路过、嘴硬到下一秒、收到你消息的我。可改动作、画风、夸张程度和回复文案。
- 照片在本地重新编码并显示预览；确认将照片发送给 MiniMax 后才允许提交。模型不负责生成中文字幕，文字在 GIF 编辑器叠加。
- 任务创建、状态查询和视频取回全部经服务端；持久化任务及按当前单价预留的预算，幂等请求避免重复提交。连接不确定时不自动再次创建收费任务。
- 成功视频用 IndexedDB 带入现有视频工作台，无需下载后重新上传。剪片段、加字、倒放／来回与 GIF 编码继续在本地进行。

## 官方接口和价格依据

2026-10-10 核对：

- [文生视频](https://platform.minimax.cn/docs/api-reference/video-generation-t2v)
- [图生视频](https://platform.minimax.cn/docs/api-reference/video-generation-i2v)：支持 Base64 Data URL，短边须大于 300px，比例 2:5 至 5:2。
- [任务状态](https://platform.minimax.cn/docs/api-reference/video-generation-query)：Preparing、Queueing、Processing、Success、Fail。
- [取回视频](https://platform.minimax.cn/docs/api-reference/video-generation-download)
- [按量计费](https://platform.minimax.cn/docs/guides/pricing-paygo)：上述文生 2 元／条，Fast 图生 1.35 元／条。预算计量依据当前公开单价，实际账单以 MiniMax 为准；价格变化时应更新服务端预算计量。

## 本地配置与运行

密钥只在 `.env.local` 中，由 `.gitignore` 排除；文件权限为当前用户读写，不进入 Vite 公开环境变量。`.env.example` 不包含密钥。

```sh
npm run dev:ai
npm run dev
```

打开 `http://127.0.0.1:5173/ai.html`。前端 `/api/ai` 经 Vite 代理连接 `127.0.0.1:8787`。

`AI_BUDGET_CNY=0` 默认禁用收费创建。用户确认本轮预算后再设置并重启服务。已做一个不创建任务的只读接口探测；该探测不证明账户具有实际视频生成余额或权限。还未提交付费视频任务。

## 验证证据

- `npm test`：45 个单元测试，包括模型选择、状态转换、错误脱敏、任务幂等、预算持久化和不确定提交不重试。
- `npm run build`：类型检查与四个页面的生产构建。
- `npm run test:video`：原有视频编辑与 GIF 导出回归。
- `npm run test:ai`：模拟 API 的异步恢复、照片确认、320/390px、预算耗尽后仍可读取结果、IndexedDB 跨页面导入和真实 GIF 编码。
- `work/ai-qa/handoff-fixture.gif` 由测试视频编码，**不是 MiniMax 生成的样片**。测试和本地密钥均不加入 Git。

## 公网部署条件

当前服务端使用单进程持久化文件账本；需要一台可运行 Node 22+、具有持久化目录的服务端。不能原样部署到多实例、无共享事务存储的无状态函数平台。启用公网绑定时必须配置内测口令、允许的前端 Origin，以及持久化目录；账户密钥始终留在服务端。

前端构建设置公开的 `VITE_AI_API_BASE=https://实际服务域名/api/ai`。服务端允许 `https://swording-k.github.io`，并通过 HTTPS 提供服务。内测口令通过前端输入，不将它编译到网页。

当前剩余：用户确认样片预算；真实文生／图生及 GIF 验收；确定公网服务端并部署。原线上工具不受这份独立分支影响。
