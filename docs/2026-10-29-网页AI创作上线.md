# 网页 AI 创作上线（2026-10-29）

## 背景

- 用户指出公开网页版没有 AI 创作，和小程序不一致；此前 2026-10-29 首次更新公开站时只构建照片整活、视频表情和反馈，AI 与账户页被排除。
- 网页 AI 依赖 CloudBase 函数、浏览器跨域预检和 COS 直传。当前 CloudBase 为免费体验版，`tcb cors add` 返回 `[CreateAuthDomain] 当前套餐无法执行此操作`，无法在控制台新增安全域名（不升级套餐）。
- 小程序 0.4.5 已提交微信审核，等待结果；用户要求 README 不再强调“未提审”。

## 变更

1. `vite.config.ts` 生产入口加回 `motion.html`、`account.html`；`src/ui/mode-nav.ts` 恢复四个入口；网页版重新提供 AI 创作与账户页。
2. `src/motion/main.ts` 生产构建默认连接现有 `https://fitgenius-d0ghm1rz21cef6594-1441969311.ap-shanghai.app.tcloudbase.com/meme-motion-api`，本地开发仍走 `/api/motion` 回环代理，`VITE_MOTION_CLOUD_ENDPOINT` 可覆盖。端点是公开值，不含密钥。
3. 云端函数环境变量 `MEME_WEB_ORIGINS` 增加 `https://swording-k.github.io`，保留原 CloudBase 静态站来源。用 `tcb config pull` 拉取完整配置 → 修改 → `tcb config update fn ... --yes` 推送；timeout（120s）、memory（512MB）、runtime（Nodejs20.19）、其他环境变量保持不变，30 分钟定时触发器保留。
4. `cloudfunctions/meme-motion/entry.mjs` 增加 `OPTIONS` 预检：允许来源返回 204 与 `Access-Control-Allow-Origin/Methods/Headers`，其他来源 403。原因是 CloudBase 网关把预检转给函数，而函数原先只接受 POST。重新 `npm run build:motion-cloud` 后用 `tcb fn code update ... --dir cloudfunctions/meme-motion` 单独更新代码（未改函数配置）。
5. COS 桶 CORS 增加 `https://swording-k.github.io`。读取现有规则后用 COS SDK `putBucketCors` 追加一条规则（GET/POST/PUT/DELETE/HEAD、`*` 请求头），保留原有规则；否则签名 PUT 上传会被 403 拦截。
6. README、小程序 README、AGENTS 与云端 README 更新：小程序改为“已提交微信审核，等待结果”；README 描述网页 AI 入口、登录/邀请码、隐私与边界。

## 边界

- 普通访客需要微信账户登录（小程序「我的 → 网页端登录」）或朋友内测邀请码；小程序审核通过前，公开可完成登录的人群有限。
- 网页 AI 只依赖供应商内容过滤，不等同微信内容安全检测；小程序 AI 仍做微信检测。
- 支付与计费保持关闭；免费模式不限内部次数，供应商费用由站主承担。
- 免费 CloudBase 套餐无法添加安全域名，后续若更换网页域名，需要同步更新 `MEME_WEB_ORIGINS`、COS 桶 CORS，并确认函数预检逻辑仍生效。
