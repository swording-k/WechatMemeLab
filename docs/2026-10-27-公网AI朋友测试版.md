## 实现与边界

- 复用既有 `meme-motion-api`、Wan provider、`meme_motion_*` 集合和 `meme-motion/` 存储前缀，未购买套餐、未修改 FitGenius 函数或数据。静态上传仅写独立子目录，不使用根目录或 `--prune`。
- Web 邀请登录签发独立 `web-motion-session` 会话；浏览器 UUID 和邀请信息绑定服务端签名身份，同一浏览器刷新可取回任务，其他浏览器不能读到其作品。30 天会话过期后由邀请码自动换新；这不是正式账户或充值系统。
- 原生入口仍校验微信会话和微信文字/图片检测凭证；Web 入口单独校验邀请会话、素材格式/尺寸和任务归属，AI 请求由阿里云处理及其服务内容过滤，不借用开发者 OpenID，不宣称 Web 已通过微信检测。公开 GitHub 反馈原安全校验未绕过。
- 浏览器按签名 PUT 上传压缩图片或参考视频，按签名 GET 下载生成结果。模型 Key、微信 AppSecret 和签名密钥只在后端。当前静态 Origin 的函数与 COS 预检实际可用，没有扩大 FitGenius 全局 CORS 配置。
- 遵循最新用户决定，不设内部金额或次数限制，仍保存调用估算与任务记录。Web 在途锁按测试浏览器隔离，每人避免重复提交，多个朋友互不阻塞；原生锁策略保留。不同浏览器不是同一正式账户，跨设备作品同步尚未实现。
- Web 云端构建需配置 `VITE_MOTION_CLOUD_ENDPOINT`；普通本地构建继续使用原 `/api/motion` 代理。正式 Pages 后续合并发布时需单独配置云端地址与对应 Origin，不能直接把普通构建当成已联网 AI 正式版。

## 重复发布步骤

1. 保留私有云配置中的 `MEME_WEB_INVITE_CODE`、`MEME_WEB_ORIGINS`、`MOTION_TEST_UNLIMITED=true` 和既有模型 Key；不将它们写入源码。`MEME_WEB_ORIGINS` 当前仅为上述静态托管 Origin。
2. `npm run build:motion-cloud`，按既有私有配置部署 `meme-motion-api`。不要部署其他函数。
3. 设置公开的 `VITE_MOTION_CLOUD_ENDPOINT` 为现有 `/meme-motion-api` HTTPS 地址，运行 `npm run build`。不要把 API Key 放进 `VITE_` 变量。
4. 从私有邀请链接取得 `try-<邀请码>.html` 文件名，将 `dist/motion.html` 复制为这个同目录入口；入口添加 `noindex,nofollow`。只把 `dist` 上传到 `meme-lab-test`。
5. 运行 `tcb hosting deploy dist meme-lab-test -e fitgenius-d0ghm1rz21cef6594 --safe --verify`，确认远端校验成功，并实际用新浏览器打开完整邀请链接。
