# 反馈入口实现计划

目标：站内整理反馈，GitHub Issue 为主要渠道，邮件为备用。保持纯静态部署，无需服务器。

1. 增加反馈页：问题类型、标题、详细描述、可选设备信息。清楚标明前往 GitHub 后才正式提交，需 GitHub 登录，内容公开；邮件备用入口不自动生成 Issue。
2. 使用共享 URL 编码模块构建 Issue 与 mailto 地址，验证中文及特殊字符、必填项和长度限制。
3. 添加 GitHub Issue 模板，默认指派 swording-k。用默认 GitHub 通知机制接收通知，实际邮件送达依赖账户设置。
4. 两个工作台的页头和页脚统一跳转本站反馈页，保留源码和作者个人网站链接。
5. 构建、浏览器验证手机与电脑反馈输入/导航，发布 Pages 并验证远程页面。不得宣称已经收信或用户完成提交。
