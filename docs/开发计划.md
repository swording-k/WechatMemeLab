# 表情包工坊开发计划

日期：2026-10-09

## 目标与定位

做一个能实际使用的中文动态表情包工具，让用户完成“上传图片 → 选动画 → 调整 → 下载 GIF → 在聊天中使用”。首版优先验证制作体验，不以未经证实的市场规模或竞品流量作为开发依据。

## 方案选择

采用浏览器本地 Canvas 渲染和 GIF 编码。相较于 AI 生成，该方案无需模型账户、生成费用或长时间等待；相较于社区平台，它能先交付完整制作链路。AI 生成和作品社区保留到用户验证之后再决定。

界面采用有趣、清晰的中文创作工作台：桌面端展示模板、预览和设置，移动端按操作顺序排列；进入页面即可试用原创示例，不需要先登录。

## 首版范围

1. 图片输入：选择文件、拖入图片；支持 PNG、JPEG、WebP；不承诺保留上传动图自身动画。
2. 六个原创模板：摸摸头、疯狂摇头、弹弹弹、转圈圈、心动、打工发疯。模板共享统一的渲染和导出接口。
3. 图片调整：缩放和裁切位置；提供重置，避免主体被误裁。
4. 个性化设置：中文短句、动画速度、背景颜色。
5. 实时预览：模板切换和设置更改后立即反馈；预览与导出复用同一渲染逻辑。
6. 导出：循环播放 GIF，提供 240px、320px、480px 方形尺寸；显示生成进度、错误和实际文件大小。
7. 微信指引：下载后由用户在客户端发送或收藏；桌面跨应用拖拽、移动端保存及收藏需要实机确认。

首版不包含登录、支付、云端照片存储、公开作品社区、AI 抠图或 AI 生成。

## 技术结构

建议使用 TypeScript、Vite 和轻量前端组件，生成可独立托管的静态站点。GIF 编码候选为 MIT 许可的 gifenc；实现前核对版本、API、透明处理和照片色彩表现。

- `src/`：界面、输入状态和错误反馈。
- `src/render/`：统一帧渲染、图片裁切和原创动画模板。
- `src/export/`：GIF 编码、进度和下载；优先在 Web Worker 中执行，避免卡住界面。
- `public/`：原创示例与必要静态资源。
- `tests/`：核心导出及浏览器流程验证。
- `docs/`：方案、验证记录和客户端兼容性结论。

输入文件先限制为 10MB，解码后缩小到合理尺寸再进入渲染流程。导出时冻结当前设置，防止生成中修改参数造成混合帧；失败后应可重新生成。控制导出帧数和像素尺寸，避免一次持有过多大图数据。

## 实施步骤及验收

### 1. 建立应用与工作台

- [ ] 初始化应用、依赖锁文件和开发命令。
- [ ] 完成中文界面、原创示例及桌面/手机布局。
- [ ] 验收：本地可打开，核心操作无需滚过营销内容即可找到。

### 2. 图片输入与实时动画

- [ ] 实现文件选择、拖入、类型/大小校验和失败反馈。
- [ ] 实现统一帧渲染及六种动画。
- [ ] 实现裁切位置、缩放、文字、速度和背景设置。
- [ ] 验收：用户图片可替换示例，每种模板有可辨识的动画，设置影响预览。

### 3. GIF 导出

- [ ] 先编写验证 GIF 输出的核心测试，再实现编码逻辑。
- [ ] 实现 Worker 编码、生成进度和 GIF 下载。
- [ ] 显示实际尺寸和文件大小，处理失败及重复生成。
- [ ] 验收：下载文件能解码、具有多帧和循环标记，文字及裁切与预览一致。

### 4. 完整交互验证

- [ ] 浏览器真实执行上传、切换模板、调整设置和下载。
- [ ] 检查所有模板的导出、长文字、小图、非法文件和重复操作。
- [ ] 检查手机布局、键盘可达性、生成过程响应和控制台错误。
- [ ] 完成生产构建并记录结果。

### 5. 交付与微信实测

- [ ] 交付开发源码、运行说明、验证记录和可访问版本。
- [ ] 将尚未验证的微信导入方式明确标注为待实测。
- [ ] 与用户确认实际客户端上的 GIF 播放、发送、收藏及拖拽体验；没有真实操作证据时不标记通过。

## 后续决策

首版试用后记录：从打开到首次下载是否顺畅、最受欢迎的模板、是否出现再次制作需求、微信使用中有哪些障碍。根据真实反馈决定扩展模板数量、加入抠图或开展 AI 功能，不提前引入账户和付费体系。
