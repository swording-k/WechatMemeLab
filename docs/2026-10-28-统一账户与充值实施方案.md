# 怪相馆统一账户与充值实施方案

## 已核对的状态

产品只有一个，网页版和原生小程序是两个客户端。原 GitHub Pages 是既有网页入口；CloudBase 的 meme-lab-test 是上轮增加的临时验收部署，不应在产品上包装成另一套账号或另一款产品。

当前小程序已用 wx.login 和已配置的 AppSecret 换取后端会话，能识别同一 OpenID，但未实现正式账户页、余额、支付订单及开发者点数豁免。网页当前邀请登录只是按浏览器隔离试用任务，不是跨设备正式账户。AI、原生及网页仍保持免费，不因新增登录方案恢复测试金额/次数门槛。本文件为下一阶段实施方案，不代表以下功能已经完成。

## 下一步实现顺序

1. 统一账户：服务端建立独立 meme_accounts 与身份关联记录，以服务端验证的微信身份创建/恢复账户，账户编号独立于客户端；不根据前端传入的 OpenID、昵称、邮箱或 isDeveloper 自动认人。小程序使用微信自动登录，账户页显示账户编号、登录状态和免费内测状态，不强制获取手机号、头像或昵称。
2. 网页账户：保留现有网页产品入口与创作功能，加入“登录/我的账户”。推荐通过已登录小程序确认网页登录码来关联同一个账户，避免仅凭邀请码或浏览器缓存当作正式账户；登录码短时、一次性、绑定发起浏览器，并必须由小程序当前用户确认。试用任务仅在证明原浏览器所有权后处理迁移，不擅自把别人的作品合并到账户。现有邀请入口继续供免费验收，正式账户完成后统一到产品主入口。二维码作为可选便利入口，不能以开发者预览码充当正式网页登录。
3. 服务端钱包与订单：创建独立 meme_wallets、meme_orders、meme_wallet_events，点数和金额使用整数。区分可用、冻结、已消费记录；发货、扣费、退款必须幂等。当前未开启收费时不扣点、不做假充值或虚构余额。开发者角色由服务端白名单控制，免产品点数并不表示模型供应商免费。
4. 接入真实虚拟支付：以账号后台实际开通能力为前提，使用 OfferID、AppKey、已发布商品及支付回调/查单核验。客户端显示支付成功不能直接增加余额。支付回调使用明确的独立配置，不覆盖已经验证的微信内容安全消息推送。用户确认每一步的价格后发起对应模型任务，查询/保存/导出已有结果不重复扣费，未知任务不自动重建。
5. 小额真机验收后发布：验收登录恢复、网页关联、订单到账、重复回调、扣费/失败处理及原有创作链路；上传新版小程序、提交审核，通过后发布。账户与免费AI版可以先更新，支付尚未开通不等于必须停掉整个产品。

## 用户手动操作

- 确认30元微信认证是否已通过。
- 在小程序后台“支付与交易 → 虚拟支付”检查开通入口，按账号要求完成个人主体及结算资料确认。
- 支付能力可用后，再按确定的充值档位创建并发布商品/道具。OfferID、商品ID可用于接入；AppKey等密钥填写到私有后端配置，不放公开代码或聊天。

现有小程序AppID、AppSecret与腾讯云后端已经配置，登录开发不需要再申请模型API或重新搭建服务器。支付能力是否已开通尚待用户确认，不把认证完成当成收款已配置。

## 外部依据（2026-10-28核对）

- 腾讯CloudBase虚拟支付集成指南：https://docs.cloudbase.net/integration/wechat-virtual-pay 。明确要求小程序认证及虚拟支付能力、OfferID/AppKey、已发布商品及真机验证；它们不由普通登录自动取得。
- 腾讯CloudBase官方工具库个人主体参考：https://github.com/TencentCloudBase/CloudBase-AI-Toolkit/blob/main/config/source/skills/cloudbase-wechat-integration/references/virtual-payment.md 。列有个人主体工具类目接入及后台开通路径；实际账号能力以用户后台为准。

未按未经核实的资质承诺网站开放平台扫码登录；当前推荐先复用已有小程序身份做确认登录，具体交互在实现前进一步验证。
